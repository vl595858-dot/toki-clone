# Telegram-бот-планировщик — инструкция по запуску

Код полностью готов. Ниже — шаги, которые нужно сделать руками, каждый занимает
несколько минут. Ни один из них не требует OAuth или Google Cloud Console —
именно этим бот проще предыдущего проекта.

## Шаг 1. Создать бота у @BotFather

1. В Telegram найди **@BotFather**, напиши ему `/newbot`
2. Придумай имя и username (должен заканчиваться на `bot`, например `moi_dela_bot`)
3. Получишь **токен** — длинную строку вида `123456:ABC-DEF...`. Сохрани его.

## Шаг 2. Создать базу данных на Supabase

1. Зайди на https://supabase.com, зарегистрируйся (можно через GitHub)
2. Создай новый проект (например `moidelishki`)
3. В разделе **SQL Editor** вставь содержимое файла `schema.sql` из этой папки, выполни (кнопка Run) — создадутся все таблицы
4. Нажми **Connect**, выбери **Transaction pooler**, скопируй строку вида `<строка подключения из панели Supabase>` — это `DATABASE_URL`

## Шаг 3. Получить ключ OpenAI (для распознавания голоса)

1. Зайди на https://platform.openai.com, зарегистрируйся
2. Создай API-ключ (API keys → Create new secret key)
3. Пополни баланс на пару долларов — распознавание голоса стоит копейки за сообщение

## Шаг 4. Отправить код на GitHub и Vercel

Точно так же, как в прошлый раз:

```
git init
git add .
git commit -m "init"
```

Создай новый пустой репозиторий на github.com (например `toki-clone`), затем:

```
git remote add origin https://github.com/ТВОЙ-ЛОГИН/toki-clone.git
git branch -M main
git push -u origin main
```

На vercel.com → Add New → Project → импортируй `toki-clone` → Deploy
(сборка упадёт без переменных окружения — это ожидаемо, идём дальше)

## Шаг 5. Переменные окружения на Vercel

Settings → Environment Variables, добавь переменные:

| Имя | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен из шага 1 |
| `TELEGRAM_WEBHOOK_SECRET` | любая случайная строка, придумай сама |
| `SETUP_KEY` | отдельная случайная строка для служебной настройки; после регистрации можно удалить |
| `APP_URL` | доверенный адрес приложения, например `https://toki-clone.vercel.app`; на Vercel можно использовать системную `VERCEL_PROJECT_PRODUCTION_URL` |
| `DATABASE_URL` | строка из шага 2 |
| `OPENAI_API_KEY` | ключ из шага 3 |
| `CRON_SECRET` | ещё одна случайная строка |
| `DEFAULT_TZ_OFFSET` | `+03:00` для Москвы (или другое смещение) |

После сохранения — Deployments → верхний деплой → три точки → Redeploy.

## Шаг 6. Зарегистрировать вебхук у Telegram

Для уже работающего бота повторная регистрация и смена ключей не нужны.
Для первоначальной настройки задай доверенный HTTPS-адрес приложения в `APP_URL`
(только origin, без пути и параметров). Если `APP_URL` не задан, маршрут использует
системную переменную Vercel `VERCEL_PROJECT_PRODUCTION_URL`.

Маршрут принимает только POST с заголовком `Authorization: Bearer <SETUP_KEY>`.
Ключ в URL больше не принимается. Из доверенного терминала с уже заданными
переменными `APP_URL` и `SETUP_KEY` выполни (без отладочного `set -x`):

```sh
curl --fail --silent --show-error --request POST \
  --header "Authorization: Bearer ${SETUP_KEY}" \
  "${APP_URL}/api/setup-webhook"
```

Ответ `{"ok":true}` подтверждает регистрацию; секрет и адрес вебхука в ответ не
попадают. После настройки можно удалить `SETUP_KEY` и выполнить redeploy: это
отключает служебную настройку, но не приём сообщений. Неверная или отсутствующая
конфигурация не приводит к вызову Telegram. Заголовки Host не используются.

## Шаг 7. Подключить cron-job.org для напоминаний

На https://cron-job.org создай задание:

- Адрес: `https://твой-адрес.vercel.app/api/cron/reminders`
- Расписание: каждую минуту
- Заголовок (Advanced → Headers): `Authorization` = `Bearer ТВОЙ_CRON_SECRET` (то же значение, что на Vercel)

Если cron-job.org сам отключит задание после серии ошибок, открой его → «Изменить» → «Включить задание» → «Сохранить».

## Шаг 8. Проверка

Открой бота в Telegram по его username, напиши или скажи голосом:

> Встреча с юристом завтра в 15:00, напомни за час

Бот должен ответить подтверждением с эмодзи и датой. За час до события придёт
отдельное сообщение-напоминание (с точностью до минуты).

Спроси и про погоду: «погода в Перми».

## Веб-планировщик и ЮKassa

На /plus описаны тарифы и опубликованы условия и контакты. В /planner пользователь входит по коду с электронной почты, создаёт и редактирует дела, ищет их и отмечает выполнение. Бесплатный тариф позволяет создать 30 дел за последние 30 дней. Веб-Плюс открывает создание без лимита и экспорт CSV на 30 дней за 290 ₽, с разовой оплатой. Дела сайта и бота хранятся отдельно. Привязка Telegram передаёт доступ к веб-тарифу при WEB_TELEGRAM_LINK=1, её можно отключить в веб-аккаунте.

### Тест в Preview

1. Используйте отдельный Supabase-проект для Preview и примените migrations/003-web-planner.sql. Укажите WEB_PLANNER_ORIGIN, WEB_SUPABASE_URL, WEB_SUPABASE_PUBLISHABLE_KEY, WEB_PLANNER_TEST_EMAIL и отдельный WEB_PLANNER_TEST_DATABASE_URL. Для TLS при необходимости укажите WEB_PLANNER_DATABASE_CA.
2. Настройте в Supabase Auth письмо с {{ .Token }}. В Preview вход разрешён одному адресу. Для публичного запуска нужен настроенный SMTP.
3. Укажите WEB_YOOKASSA_MODE=test, ID и ключ тестового магазина, отдельный случайный WEB_YOOKASSA_HOOK_KEY из 32–128 символов и тестовые параметры чека. Чтобы открывать заказы, задайте WEB_YOOKASSA_CHECKOUT_PAUSED=0.
4. Подпишите магазин на payment.succeeded, payment.canceled, refund.succeeded по адресу https://<host>/api/planner/yookassa/<HOOK_KEY>. В Preview портал ЮKassa должен иметь доступ к этому адресу. Не публикуйте ключ и адрес уведомлений.
5. Войдите по почте, создайте дело, ознакомьтесь с офертой и оплатите [тестовой картой](https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing). Проверьте чек, активацию, отмену, полный и частичный возврат и повторную доставку уведомления.

Сайт открывает доступ только после авторизованного запроса к API ЮKassa. Идентификатор заказа используется для идемпотентности. Повтор неизвестного результата создания ограничен 30 минутами. По истечении окна оператор сверяет заказ в кабинете ЮKassa перед ручным закрытием, чтобы предотвратить повторное списание. При полном возврате соответствующий период исключается из расчёта. В боте веб-доступ и подарочный доступ действуют до более поздней из двух дат.

### Рабочий запуск

Проверьте оплату, отмену, возврат и чеки в тестовом магазине. Подтвердите тексты оферты и политики данных. Выберите размещение БД и Auth с учётом применимых требований к персональным данным. Веб-планировщик поддерживает отдельную базу и Supabase Auth на собственном HTTPS-домене. В Production примените миграцию к отдельной веб-базе, настройте SMTP, укажите WEB_PLANNER_DATABASE_URL и включите WEB_PLANNER_PUBLIC_READY=1 после проверки входа. Проверьте с ЮKassa параметры и схему формирования чека. Реализован одностадийный расчёт full_payment. После проверок сконфигурируйте рабочий магазин, WEB_YOOKASSA_MODE=live, WEB_YOOKASSA_LIVE_APPROVED=1 и WEB_YOOKASSA_CHECKOUT_PAUSED=0. Чтобы остановить приём новых заказов и продолжить принимать уведомления, поставьте WEB_YOOKASSA_CHECKOUT_PAUSED=1. Версия оферты сохраняется в заказе.

Старый тестовый checkout с обязательной привязкой Telegram снят с эксплуатации. Миграция 001-plus-test.sql оставлена в истории.

Чтобы показать оферту и контакты на `/plus`, укажите на сервере `PLUS_SELLER_NAME`, `PLUS_SELLER_INN`, `PLUS_SELLER_OGRNIP` и `PLUS_SUPPORT_EMAIL`. `PLUS_SUPPORT_PHONE` добавляет телефон, если он указан. Эти данные отображаются на сайте при настройке, поэтому используйте реквизиты, предназначенные для публикации.

## Тарифы и подарочные промокоды

Примените `migrations/002-plus-plans.sql` до выкладки. В `PLUS_ADMIN_TELEGRAM_ID` укажите числовой Telegram ID владельца. В личном чате бот показывает ваш собственный ID командой `/myid`. Владелец отправляет `/promogive`, выбирает 30 дней или год и пересылает получателю готовую команду `/promo КОД`. Код действует 30 дней с выдачи, активируется один раз и добавляет выбранный срок доступа (30 или 365 дней). Администратор может выдать отдельный код каждому человеку. Бот хранит только хеш кода. `/plus` показывает тариф и срок доступа.

`PLUS_PLANS_ENABLED=1` включает учёт и проверку лимитов за последние 30 дней. Бесплатный тариф — 30 новых дел и 30 голосовых, фото доступны с Плюсом. Плюс — без лимита на новые дела, до 120 голосовых и до 30 фото или скриншотов. Повторяющееся дело расходует одну запись при создании шаблона. Автоматические повторы, перенос и удаление дела лимит не расходуют.

Для рекламы владелец отправляет `/promocampaign 100`, где 100 — максимум активаций. Полученную Telegram-ссылку можно вставить в ChatPlace или Instagram. Кампания открыта 30 дней с выпуска. Аккаунт может использовать код кампании один раз и получает 30 дней Плюса с момента активации или в дополнение к уже активному доступу. Для альтернативного бота укажите имя без @ в `PLUS_BOT_USERNAME`.
