# CLAUDE.md — «Мои делишки»

## Что это
Telegram-бот-органайзер @moideladelishki_bot и Mini App «Календарь».
Принимает текст и голос: создаёт, переносит и удаляет дела, делает повторы и напоминания, показывает погоду.
Владелец — Андрей, ИП, пишет по-русски. Обращаться в мужском роде. Часовой пояс: Пермь +05:00.

## Стек и версии
- Next.js 14.2.5 (Pages Router), React 18.3.1, pg 8.12.0, JavaScript (не TypeScript)
- Vercel Hobby (автодеплой из ветки main), БД Supabase Postgres (проект moidelishki, Transaction pooler)
- OpenAI: Whisper (голос) и gpt-4o-mini (разбор фразы в JSON, temperature 0)
- Open-Meteo: погода, геокодер, часовой пояс города (без ключа)
- Напоминания: cron-job.org раз в минуту вызывает /api/cron/reminders с Bearer CRON_SECRET
- Секреты ТОЛЬКО в переменных окружения Vercel. В репозиторий и в этот файл ключи не писать.

## Структура файлов
- pages/api/telegram/[secret].js — только роутер (~170 строк): handler (вебхук), handleUpdate (голос, /start, загрузка памяти, разбор фразы), dispatch (выбор обработчика по intent)

- lib/handlers/calendar.js — команда /calendar (сообщение с кнопкой, открывающей Mini App)

- lib/handlers/recurringEdit.js — кодовые слова для повторяющихся дел: «навсегда» (перенос всей серии), «переименуй» (новое название)
- lib/handlers/reminderButtons.js — кнопки под напоминанием «✅ Сделано» и «📅 Перенос» (callback_data rem:done:<id> / rem:move:<id>)
- lib/handlers/timezone.js — команда /timezone, ответ городом, вопрос о городе новым пользователям (после /start)
- lib/handlers/events.js — создание одного дела, список предстоящих
- lib/handlers/eventTarget.js — общий поиск дела по названию или «последнее из памяти» (resolveTarget, replyNotFound)
- lib/handlers/eventsEdit.js — удаление и перенос дела
- lib/handlers/reminders.js — отмена и установка напоминания у существующего дела
- lib/handlers/recurring.js — создание и остановка повторяющихся дел
- lib/constants.js — дни недели, месяцы, размер буфера повторов (8)
- lib/text.js — защита от слов из памяти в названии нового дела (stripContextWords)
- lib/contextText.js — справка для модели о состоянии разговора (buildContextText)
- lib/ai.js — Whisper и разбор фразы моделью (промпт с правилами intents)
- lib/time.js — все операции с датами, часовыми поясами и повторами
- lib/weather.js — погода и часовой пояс города
- lib/dayBefore.js — второе напоминание накануне в 12:00 для дней рождения
- lib/dedupe.js — защита от повторов вебхука Telegram (таблица processed_updates, создаётся сама)
- lib/context.js — память диалога; lib/settings.js — часовой пояс чата
- lib/telegram.js — отправка сообщений и файлов; lib/telegramAuth.js — проверка initData; lib/db.js — подключение к БД
- pages/api/cron/reminders.js — рассылка напоминаний и пополнение повторов
- pages/api/webapp/* — API для календаря; pages/calendar.js — Mini App
- schema.sql — справочная копия схемы БД
Принцип: один файл = одна тема, ориентир 50–150 строк. Чтобы поправить поведение — открывать только нужный файл из lib/handlers/.

## Технические решения
- Даты в БД хранятся в UTC (timestamptz). Конвертация только через lib/time.js.
- У каждого чата свой часовой пояс (user_settings.tz_offset); по умолчанию DEFAULT_TZ_OFFSET.
  Задаётся автоматически из браузера в календаре, командой /timezone или вводом города текстом.
- Повторы (daily, weekly, monthly, yearly): таблица recurring_events + буфер из 8 экземпляров в events. Cron пополняет буфер.
- Память диалога: chat_context (jsonb, живёт 1 час). stripContextWords убирает слова из памяти из названия нового дела.
- Модель не считает даты: «через N минут» считает код (event_relative_minutes).
  Модели ЗАПРЕЩЕНО вычислять remind_offset_minutes разностью времён.
- Вебхук сначала дожидается обработки и только потом отвечает 200 (maxDuration 10).
- Mini App: авторизация по initData (HMAC-SHA256), заголовок Authorization: tma <initData>.
- Очистка: раз в неделю (воскресенье 22:00 UTC) cron удаляет дела старше 30 дней, выполненные и нет (pages/api/cron/reminders.js).
- «Сделано» = events.done_at; у повторяющегося отмечается только этот экземпляр; сделанные дела не напоминаются, в списках показываются с ✅.
- Кодовые слова решает код (lib/text.js: hasForeverWord, parseRename), а не модель: «навсегда»/«насовсем» + reschedule_event → reschedule_recurring_event; «переименуй» → rename_event.
- Дни рождения: lib/text.js isBirthday + create_recurring_event → напоминание по умолчанию за 7 суток (10080 мин), время по умолчанию 10:00; явный интервал в тексте главнее.
  Второе напоминание «накануне в 12:00» (lib/dayBefore.js, вызывается из cron): recurring_events.day_before + events.reminded2.
- Таблицы БД: events, recurring_events, chat_context, user_settings, processed_updates (см. schema.sql).

## Известные баги и что пробовали
- cron-job.org сам отключает задание после серии ошибок 500. Лечение: «Изменить» → «Включить задание» → «Сохранить».
- «напомни … в 13:00» путалось с set_reminder. Исправлено правилами в lib/ai.js. Не ломать их.
- Модель добавляла слова из памяти в название дела. Исправлено через stripContextWords.
- GitHub Actions по расписанию ненадёжен — заменён на cron-job.org, возвращаться не нужно.
- Старые повторяющиеся дела без буфера нужно пересоздать вручную.
- Отложено: переспрашивание при нескольких похожих делах; несколько напоминаний на одно дело (нужна смена схемы БД);
  смена ключей безопасности; список разрешённых чатов и лимит трат OpenAI.

## Правила работы
1. Никогда не переписывать файл целиком ради маленькой правки.
2. Показывать только изменённые функции или блоки: название файла, место вставки или формат «найти / заменить».
3. Если нужен файл, которого не видно, попросить его. Не угадывать и не писать код вслепую.
4. Перед исправлением ошибки кратко назвать причину и затронутые файлы.
5. Не менять то, о чём не просили. Не «улучшать» код попутно.
6. Если правка затрагивает больше 2–3 файлов, предупредить заранее.
7. Отвечать коротко, без повторного вывода кода и лишних тестов: у пользователя тариф Pro, лимиты часто упираются.
8. Говорить по-русски, в мужском роде. Не писать голое слово «расширение», а всегда «расширение Claude for Chrome на вкладке <сайт>».
9. Проверка JSX: node -c не годится, использовать npx --no-install tsc --noEmit --jsx preserve --allowJs --target es2020 файл.jsx
10. Большие файлы пользователь грузит на GitHub через «Upload files», малые правки через блоки кода.
